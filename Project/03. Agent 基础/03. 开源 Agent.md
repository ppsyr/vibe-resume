### 1. 参考了哪个开源项目 / 为什么选它

```
我没有完整照搬某一个开源 agent，而是从几个方向吸收了设计。

最直接的影响来自 LangChain 和 LangGraph 的 middleware 体系。我的 20 个中间件按固定顺序挂在 before_model、after_model、wrap_model_call 这些钩子上，治理、记忆、技能、沙箱都是可插拔的横切关注点。这个思路和 OpenHands V1 的设计原则是一致的——组件可组合、无状态、单一状态源，应用和 agent 核心分离 。我选这个方向，是因为我的任务形态是长任务研究，治理复杂度高，需要一个结构化的、可预测的治理链，而不是把所有逻辑塞进一个循环里。

工具接口的设计上，我受 SWE-agent 的 ACI 思路影响。SWE-agent 的核心贡献是证明工具接口本身要专门为模型设计，而不是简单暴露 bash，比如文件查看器每轮只显示 100 行、搜索只列出文件名不展示上下文 。我的沙箱工具也做了类似的事：路径校验、读写权限检查、MCP 工具的描述扫描守卫，工具不是裸暴露，接口本身有治理。

Pi 的极简路线我了解过，但没有选。Pi 默认只给四个工具，系统提示词不到 1000 token，赌的是前沿模型已经天生知道怎么当 coding agent 。这个判断在 coding 场景可能成立，但我的项目是研究型长任务，需要记忆、技能、多 Agent 协作、上下文治理，极简路线兜不住这些复杂度。所以我的取向和 Pi 是相反的——它做减法，我做加法，但加法是有结构的加法，不是堆功能。

另外，我的多 Agent 专家协作直接接了 Pi、Codex、Claude 作为外部专家，所以我对它们的运行时形态有实际接触，不是纯读文档。这也是我了解这些框架的一个真实渠道。
```

### 2. 你的 Agent 相比开源的 Agent，优势和劣势是什么？

```
和主流 Agent 比，我先说劣势。

对比 Claude Code：它压缩后自动重注入规则、记忆、最近文件、skill，我的快照回读靠模型主动触发，不是系统强制。它的权限是 harness 强制不是模型自己判断，六档含自动审批，我的沙箱是不合规直接拒绝，没有审批流。

对比 Codex：它的审批是 App Server 反向 RPC、turn 暂停等人回答，可恢复；我有拦截没审批。它的双轴权限把沙箱等级和审批策略分开，我的权限粒度没到那个程度。它还有 auto_review 自动评审 agent，我没有。

对比 Pi：Pi 的工具搜索和渐进式披露，MCP 工具不全量塞上下文，按需加载；我是启动时全量注册，工具多了选择困难没专门处理。Pi 的极简内核让扩展不进核心，我的 20 个中间件是固定顺序写死的，加治理要改挂载。

对比 DSH：它的会话日志是唯一真相源，模型看到的一切都被记录，可回放可分叉；我的 journal 是事件流，快照是整份 JSON 取回，没有内部检索，能回放但不是一等公民。

优势我讲三个。第一，会话持久化更工程化，SQLite 落盘、元数据用户级、跨进程恢复有验收，Claude Code 的 auto memory 是机器本地的。第二，约束有独立归属，Claude Code 的记忆是软上下文，要拦截得用 hook，我专门做了约束栏目，虽然还是 LLM 识别不是规则钉住。第三，评测和归因有真实证据，P4 那次 0/3 到 3/3、两处独立问题的隔离复测，是可展示的，不是口头说方案好。

所以准确说：我不在任何一条主流路线上，是 LangGraph 加固定中间件的形态；劣势在恢复自动化、审批可恢复、工具懒加载、真相源设计，优势在持久化、约束归属、可展示的归因证据。
```

### 4. Codex 和 Claude Code 的设计理念有什么不一样？

```
Codex 和 Claude Code 的设计理念差异，我理解核心在 harness 的定位上。

Claude Code 走的是“极简循环加极厚护甲”的路线。它的决策逻辑只占代码库的 1.6%，剩下 98.4% 全是运行时基础设施——权限、压缩、工具执行、安全。它不告诉模型“你应该先读文件再写代码再跑测试”，它只提供工具，让模型自己决定下一步。这背后有一个信念：对足够强的模型，显式的调度脚手架不是帮助，是束缚。它的复杂度不在编排逻辑里，在护甲厚度里。

Codex 走的是“harness 即平台”的路线。它把 Agent Loop 本身当成可复用的东西，通过 exec、SDK、app-server 三层入口开放出去。它的 app-server 用反向 JSON-RPC 支持审批请求——Agent 需要批准时，服务器向客户端发请求，暂停轮次，等人回答再继续。它的目标不是做一个更好的 coding agent 界面，是让开发者把 Agent 嵌进自己的产品，客服后台还是客服后台，安全看板还是安全看板，Codex 在下面跑循环。

所以两者最根本的不同是：Claude Code 在优化“模型在终端里怎么把活干好”，Codex 在优化“harness 怎么被别的产品复用”。一个向内做厚护甲，一个向外做开放平台。
```
